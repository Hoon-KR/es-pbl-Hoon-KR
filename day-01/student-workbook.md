## 왜 ES 수업에서 검색을 먼저 설계하나요?

ES는 검색 요구를 실제 데이터와 요청으로 구현하는 도구입니다. 따라서 먼저 사용자가 무엇을 찾는지, 어떤 결과가 맞는지, 무엇을 제외해야 하는지를 정합니다. 그다음 ES의 index·mapping·query·aggregation으로 구현하고, 결과와 근거를 검증합니다. 이 과정에서 검색은 별도 이론이 아니라 ES 설계와 구현의 출발점입니다.

### 학습 목표

- 학생이 ES는 JSON 문서를 색인하여 검색·filter·sort·aggregation 요청에 응답하는 엔진입니다.

### 핵심 개념

문서 단위, 검색어, 분석 질문이 한 문장에 모두 들어가야 합니다.

**주의:** ES가 웹 화면·회원·결제를 대신한다는 오해를 바로잡습니다.

### 관계형 DB와 ES 색인 구조 비교

다음 대응은 처음 구조를 이해하기 위한 비교입니다. 이름과 목적이 완전히 같은 것은 아닙니다.

| 비교 | 관계형 DB | Elasticsearch |
|---|---|---|
| 논리적 묶음 | `table` | `index` |
| 데이터 한 건 | `row` | `document` |
| 속성 | `column` | `field` |
| 구조 정의 | table schema | `mapping` |
| 주된 목적 | 원본 업무 데이터·거래 | 검색·filter·sort·aggregation |
| 검색 준비 방식 | 조건 조회 중심 | text를 token으로 분석하고 역색인 생성 |
| 데이터 관계 | 정규화·join을 활용할 수 있음 | 필요한 검색 field를 document에 함께 둘 수 있음 |

**중요:** `table = index`처럼 1:1로 완전히 같은 개념은 아닙니다. 관계형 DB는 업무 데이터의 정합성과 거래를, ES는 검색·분석을 빠르게 하기 위한 색인 구조를 우선합니다. 내 PBL에서는 원본 DB의 구조를 그대로 복사하기보다, 사용자가 찾고 조건을 적용할 정보를 어떤 document와 field로 색인할지 결정합니다.

### Elastic Stack 데이터 흐름과 이번 과정의 범위

업무 데이터는 앱·DB·서버 로그·파일처럼 여러 원천에서 옵니다. ES로 넣기 전에는 데이터를 가져오거나 필요한 형태로 정리하는 단계가 있을 수 있습니다.

`원천 데이터 → (선택) 수집·전처리 → Elasticsearch → Kibana`

| 도구 | 한 줄 역할 | 이번 과정 |
|---|---|---|
| Filebeat | 서버의 로그 파일을 가볍게 전달 | 개념만 이해 |
| Elastic Agent | 로그·지표·보안 데이터를 통합 수집 | 개념만 이해 |
| Logstash | 여러 입력을 받아 변환·분기 | 개념만 이해 |
| Connector | 외부 서비스·콘텐츠를 ES와 동기화 | 개념만 이해 |
| Elasticsearch | 문서를 색인하고 검색·filter·sort·집계를 처리 | 직접 사용 |
| Kibana | ES 문서를 탐색·시각화하고 Dashboard로 설명 | 직접 사용 |

이번 PBL은 수집 도구를 설치하지 않습니다. Day 2에서 PowerShell 생성기로 데이터를 만들고 Bulk NDJSON으로 ES에 직접 색인한 뒤, Day 4에 Kibana에서 확인합니다.

### 원천값에서 ES 문서까지

같은 상품이라도 원천 데이터와 ES 문서는 값의 형태가 다를 수 있습니다.

| 단계 | 예시 |
|---|---|
| 원천 CSV | `상품명: SoundLab 무선 이어폰`, `가격: "89000"`, `재고: Y` |
| 정리된 JSON | `{"name":"SoundLab 무선 이어폰","price":89000,"in_stock":true}` |
| Elasticsearch | `name`은 검색, `price`는 숫자 filter·정렬·집계, `in_stock`은 참·거짓 filter에 사용 |
| Kibana | 같은 ES 문서로 상품 수, 가격 분포, 검색 결과를 확인 |

값을 `"89000"`에서 숫자 `89000`으로, `Y`에서 boolean `true`로 정리해야 가격 범위 검색·정렬·집계를 정확히 할 수 있습니다. Kibana는 데이터를 새로 만드는 곳이 아니라 ES에 색인된 같은 문서를 읽어 결과와 차트로 보여 줍니다.
